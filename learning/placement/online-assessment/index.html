Online assessments: aptitude, coding and proctoring

What online tests contain, how to manage time, and rules you must not break.

← PreviousLinkedIn and job-portal profiles recruiters find Next lesson →The technical interview: what freshers are asked

Online assessments filter large applicant pools, so the goal is to clear the cut-off, not to score 100%. They usually contain some of these sections:

  • Quantitative aptitude — percentages, ratios, time and work, speed and distance, interest. Practise in the Aptitude track.
  • Logical reasoning — series, coding-decoding, arrangements, syllogisms.
  • Verbal ability — grammar, reading comprehension, sentence correction.
  • Coding — one to three problems in a language of your choice, checked against hidden test cases. Practise in the DSA track.
  • Technical MCQs — output of short code, OOP, DBMS and OS basics.

Time strategy

  1. Read the rules first: is there negative marking? Can you return to a question?
  2. Do one pass answering what you know quickly; mark the rest.
  3. In coding, first write a simple correct solution that passes basic cases, then optimise if time remains — partial test-case credit is common.

Proctoring rules

Many tests use webcam and screen monitoring. Use a quiet room, a charged laptop and a stable connection; don't switch tabs, use a second device or have someone help. Violations can disqualify you from that company for a long period.

Worked example

Adapt it to your situation
Coding question: "Return the second largest distinct number in a list."

Step 1 — simple and correct (passes most cases): sort the distinct values, return the second last

Step 2 — handle edge cases the hidden tests will try:
  • list with one element        → return -1 (as the problem states)
  • all elements equal           → return -1
  • negative numbers             → still works

Step 3 — only if time remains: single pass, O(n), no sorting

What to notice

• Getting a correct answer first secures partial or full marks.
• Hidden test cases almost always include edge cases — empty, single element, duplicates, negatives. Read the constraints for them.
• Optimise last; an elegant solution that fails edge cases scores less.

Names, companies and numbers are fictional examples. Always confirm details on the employer's official site.

Key points

  • Aim to clear the cut-off, not to be perfect.
  • Check negative marking before guessing.
  • Correct first, then edge cases, then optimise.
  • Follow proctoring rules strictly.

Quick check

In a coding test with hidden test cases, what should you do first?

A correct solution with edge cases handled usually earns most of the marks; optimise only after that.

Practice task

Take a timed 30-minute aptitude set from the Aptitude track, then one coding problem from the DSA track in 25 minutes. Note which topics cost you the most time.

Interview corner

Your test score was average. Why should we move you forward?

Acknowledge it briefly, then point to evidence of your ability — projects, a skill you've improved since, or how you solve problems — without making excuses.

Which language did you use in the coding round and why?

Name it and give a practical reason: you know its standard library well, it's what you used in projects, or it suits the problem.
