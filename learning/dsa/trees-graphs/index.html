Trees & graphs: BFS and DFS

Traversing trees and graphs, shortest paths in unweighted graphs.

← PreviousSorting algorithms You finished DSA →Explore all learning

A tree is a hierarchy of nodes with one root and no cycles (folders, org charts, the HTML DOM). A binary search tree keeps smaller values on the left and larger on the right.

A graph is nodes connected by edges — cities and roads, people and connections. Store it as an adjacency list: a dict mapping each node to its neighbours.

  • DFS (depth-first) goes deep before wide — recursion or a stack. Good for exploring all paths, detecting cycles, counting connected parts.
  • BFS (breadth-first) visits level by level with a queue — gives the shortest path in an unweighted graph.

Always track visited nodes in a graph to avoid infinite loops.

Key points

  • Adjacency list = dict of neighbours.
  • BFS + queue = shortest path (unweighted).
  • DFS + recursion/stack = explore deeply; track visited.

Quick check

Which traversal finds the shortest path in an unweighted graph?

BFS explores in order of distance, so the first time it reaches the goal is via a shortest path.

Practice task

Write count_islands(grid) that counts groups of connected 1s (up/down/left/right) in a 2-D list using DFS.

Interview corner

Why does inorder traversal of a BST give sorted output?

BST rules put smaller keys in the left subtree and larger in the right, so visiting left, node, right outputs keys in ascending order.

BFS vs DFS memory use?

BFS stores a whole frontier level (can be wide); DFS stores the current path (can be deep). Choose based on the graph's shape and what you need.
