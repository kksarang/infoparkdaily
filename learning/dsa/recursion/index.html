Recursion & backtracking

Functions that call themselves, base cases, memoisation and generating combinations.

← PreviousLinked lists Next lesson →Binary search

A recursive function solves a problem by calling itself on a smaller version of it. Every recursive function needs:

  1. a base case that returns without recursing, and
  2. a recursive case that moves towards the base case.

Repeated sub-problems (like Fibonacci) explode exponentially — cache results with memoisation (functools.lru_cache) to make them linear. This is the start of dynamic programming.

Backtracking builds a solution step by step, undoing a choice (“backtracking”) when it can't lead to an answer — used for subsets, permutations and puzzles.

Key points

  • Always define the base case first.
  • Memoise overlapping sub-problems.
  • Backtracking = choose, explore, un-choose.

Quick check

What happens if a recursive function has no reachable base case?

Without a base case the calls never stop, and Python raises RecursionError.

Practice task

Write permutations(s) that returns every ordering of the letters in a short string such as "abc".

Interview corner

Recursion vs iteration?

Recursion is often clearer for trees and divide-and-conquer but uses call-stack memory; iteration avoids stack limits. Most recursion can be rewritten with an explicit stack.

What is memoisation?

Caching the results of function calls by their arguments so repeated sub-problems are computed once — top-down dynamic programming.
