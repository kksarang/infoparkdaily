Events & forms

Handling clicks and input, and building controlled form fields.

← State with useState Lists, keys & conditional rendering →

React events use camelCase props: onClick, onChange, onSubmit. Pass a function, don't call it: onClick={save}, not onClick={save()}.

Controlled inputs

In a controlled input, React state is the single source of truth: the input's value comes from state, and onChange updates that state. This makes validation and resetting easy.

Call e.preventDefault() in onSubmit to stop the browser reloading the page.

Key points

            
  • Pass handlers, don't call them.
  • Controlled input: value + onChange from state.
  • preventDefault in onSubmit.

Interview corner

            
Controlled vs uncontrolled inputs?
Controlled inputs keep their value in React state. Uncontrolled inputs keep it in the DOM and you read it with a ref when needed.

            
Why does onClick={handle()} cause problems?
It calls handle during render and passes its return value as the handler — often causing loops if it sets state.
